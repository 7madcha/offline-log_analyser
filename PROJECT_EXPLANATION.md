# Project File Explanation

This project is fully local. It analyzes CSV files that are already on the machine or synthetic data generated by the app. It does not connect to company infrastructure, external APIs, VPNs, firewalls, or credentialed systems.

## Root files

### `.gitignore`
Keeps local-only files out of Git, including the virtual environment, Python caches, generated CSV outputs, generated PDF reports, and Codex-local folders.

### `README.md`
Explains the project purpose, setup commands, synthetic data generation, CLI usage, dashboard usage, tests, project structure, detection rules, risk scoring, limitations, and ethical boundaries.

### `requirements.txt`
Lists the Python packages needed to run the project: pandas, numpy, dash, plotly, pyyaml, scikit-learn, reportlab, pytest, and playwright.

### `config.yaml`
Stores all required CSV columns and detection thresholds. The detector code reads thresholds from this file instead of hardcoding values.

### `main.py`
Runs the command-line pipeline. It loads config, loads a CSV, validates it, cleans it, runs detectors, correlates incidents, exports CSV files, creates a PDF report, and prints a summary.

### `app.py`
Runs the Plotly Dash interactive dashboard. It provides the local data selector, one-click Run analysis button, fake log generation, CSV upload, existing-file analysis, filters, charts, alert and incident tables, investigation timeline, CSV template download, and PDF report download.

## Assets folder

### `assets/theme.css`
Contains local CSS styling and custom design rules for the Plotly Dash interface.

## Data files and folders

### `data/raw/.gitkeep`
Keeps the optional raw-data folder visible in Git. This folder is for local CSV files the user may receive and place manually.

### `data/processed/.gitkeep`
Keeps the processed-data folder visible in Git. The CLI writes `cleaned_logs.csv` here, but generated CSVs are ignored.

### `data/synthetic/firewall_logs.csv`
A generated local synthetic firewall dataset. It uses private and documentation IP ranges only, not real company logs.

## Output folders

### `outputs/alerts/.gitkeep`
Keeps the alerts output folder visible in Git. The CLI writes `alerts.csv` here, but generated CSVs are ignored.

### `outputs/incidents/.gitkeep`
Keeps the incidents output folder visible in Git. The CLI writes `incidents.csv` here, but generated CSVs are ignored.

### `outputs/reports/.gitkeep`
Keeps the reports output folder visible in Git. The CLI writes `incident_report.pdf` here, but generated PDFs are ignored.

## Source package

### `src/__init__.py`
Marks `src` as a Python package so modules can import each other cleanly.

### `src/utils.py`
Contains shared helpers for reading YAML configuration, creating directories, and safely joining display values.

### `src/loader.py`
Loads CSV files into pandas dataframes and raises clear errors for missing, empty, or invalid files.

### `src/validator.py`
Checks whether the loaded dataframe has the required columns, duplicate columns, and usable rows before analysis continues.

### `src/cleaner.py`
Normalizes the dataset. It parses timestamps with the expected format, normalizes actions and protocols, converts numeric fields, validates IPv4 addresses and ports, removes invalid rows, and returns a cleaning summary.

### `src/generate_logs.py`
Creates local synthetic firewall logs. It supports `normal`, `noisy`, and `attack-heavy` profiles and never uses real public or company IP addresses.

### `src/detectors.py`
Contains independent threshold-based detectors for repeated blocked connections, port scans, host scans, large outbound transfers, and suspicious off-hours activity. It combines alerts and assigns alert IDs.

### `src/correlator.py`
Groups related alerts into incidents when they involve the same source IP inside the configured correlation window. It assigns incident IDs and attaches score, severity, explanation, and recommendations.

### `src/scoring.py`
Calculates incident risk scores from alert types using values from `config.yaml`. It caps the score at 100 and maps scores to Low, Medium, High, or Critical severity.

### `src/explanations.py`
Builds human-readable incident explanations from actual incident values. It avoids unsupported claims such as saying a host is compromised.

### `src/recommendations.py`
Maps alert types to advisory investigation recommendations. It does not execute any response action.

### `src/exporter.py`
Writes cleaned logs, alerts, and incidents as UTF-8 CSV files while creating output folders automatically.

### `src/reporting.py`
Builds the CSV schema template and creates a local PDF incident/risk report without external dependencies or external services.

# New AI and traffic features

Isolation Forest is an unsupervised machine-learning method that isolates unusual records with random decision trees. Here, one record describes one source IP during one configurable time window. The model uses only numeric behavior—not IP or timestamp strings—and runs entirely on the computer.

The AI anomaly score is normalized from 0 to 100. Higher means more different from the learned baseline. When at least five windows contain only reliable normal labels (`normal`, `benign`, `legitimate`, `0`, or `false`), the model trains on those windows; otherwise it trains on all loaded windows and displays a warning. A result is marked anomalous only when Isolation Forest predicts `-1` and the normalized score meets the configured threshold. The export also includes the raw score and direct model prediction. The explanation compares actual window values with dataset medians and reports up to three strongest differences. An anomaly is not definitive evidence of an attack: a backup, maintenance job, synthetic dataset, or an unusual but legitimate user can look anomalous.

## Rule-Based Detection vs AI Anomaly Detection

Rule-based detectors recognize known patterns such as scans or repeated blocked connections. Isolation Forest finds behavior that differs from the general baseline. The two methods complement each other, and a human should validate AI findings against raw events and business context. With unlabelled data, the current file becomes the baseline; if it contains many attacks or too little representative traffic, results can be less reliable.

The source-IP ranking counts events per source, then calculates allow/block totals, blocked ratio, unique targets and ports, byte totals, alert count, and maximum incident risk. The destination-port ranking counts contacts per port and adds source/destination diversity, actions, bytes, and a common-service name. Dashboard filters are applied before these summaries are calculated.

Run the CLI with `.venv\Scripts\python.exe main.py --input data\synthetic\firewall_logs.csv` or start the dashboard with `run.bat` (or `.venv\Scripts\python.exe app.py`). New exports are written to `outputs/ai/anomalies.csv`, `outputs/analytics/top_source_ips.csv`, and `outputs/analytics/top_destination_ports.csv`. Settings live under `ai_detection`, `analytics`, and `working_hours` in `config.yaml`; invalid values fall back to safe defaults.
